# ضمان الجودة

## 1. الفحص الآلي

```bash
npm run verify
```

يشغّل فحص Manifest وCSP والأذونات والملفات والخطوط، ثم 72 اختبارًا تغطي:

| الملف | ما يحرسه |
|---|---|
| `tests/settings.test.mjs` | عقد الإعدادات، تطبيع النطاقات، أسبقية قواعد المواقع، المظهر. |
| `tests/background.test.mjs` | تخزين Service Worker، الترحيل، الشارة لكل تبويب، سلوك الاختصارات على موقع تحكمه قاعدة، بوابة الإيقاف العام. |
| `tests/options.test.mjs` | دورة تحرير المواقع، منع «التخصيص الشبح»، قبول كل نطاق يقبله العقد المشترك. |
| `tests/contract.test.mjs` | تطابق نسخة العقد داخل `content.js` مع `src/shared/*` (بما فيها نمط التحقق من النطاقات)، وعدم وجود رسائل ميّتة. |
| `tests/design-system.test.mjs` | طبقة الرموز الواحدة، أرضية 11px، غياب الألوان الخام، تطابق كتلتي المظهر الداكن. |
| `tests/ui-separation.test.mjs` | فصل مظهر الأداة عن أوضاع الصفحة، صدق اللوحة ونطاق تحريرها، حصر الحجم والتباعد في النثر، وحدة المقاس، التحديث في المكان بدل إعادة البناء، متابعة تغيّر المقاس، ترويسة المقال، وجذور الظل. |

## 2. الفحص في المتصفح

بعض السلوك لا يمكن اختباره دون DOM حقيقي، والمشروع بلا تبعيات. لذلك توجد بيئة تشغيل محلية
تُحمّل الكود المشحون نفسه مع محاكاة `chrome.*`:

```bash
npm run harness
```

| العنوان | يغطّي |
|---|---|
| `/tests/harness/popup.html` | اللوحة كاملة. المعاملات: `?theme=dark`, `?page=protected`, `?page=reload`, `?host=…`, `?readingRoot=false` |
| `/tests/harness/options.html` | صفحة إدارة المواقع كاملة. |
| `/tests/fixtures/content-harness.html` | المحرك مع محاكاة `chrome.*` مضمّنة في الملف نفسه — أسرع طريقة لفتح المحرك بلا معاملات. |
| `/tests/fixtures/engine-regressions.html` | تراجعات المحرك في 1.2: تبديل `class`، إعادة كتابة `style`، رشقة التخزين. |
| `/tests/fixtures/real-article.html?mode=reading` | مقال عربي/إنجليزي بخط مصمم واتجاه صريح وكود وأزرار. |
| `/tests/fixtures/github-like-grid.html?mode=reading` | تطبيق شبكي مع شريط جانبي ومقال داخلي. |
| `/tests/fixtures/app-no-article.html?mode=reading` | تطبيق ديناميكي بلا مقال موثوق. |

### تشغيل المحرك على صفحة حقيقية

سياسات CSP تمنع حقن السكربت في المواقع مباشرة، لذا تُلتقط الصفحة ثم تُشغَّل محليًا:

```bash
curl -sL -A "Mozilla/5.0 … Chrome/131" "https://github.com/<user>" -o /tmp/page.html
```

ثم استبدل الروابط النسبية بمطلقة، احذف سكربتات الصفحة و`<meta http-equiv="Content-Security-Policy">`،
وأضف قبل `</body>`:

```html
<script src="/tests/harness/page-mock.js"></script>
<script src="/src/content/content.js"></script>
```

ضع الملف داخل المستودع مؤقتًا وافتحه عبر `npm run harness`. لا تُضِف اللقطات إلى المستودع.

تقبل صفحات `fixtures/` أي مفتاح من عقد الإعدادات كمعامل استعلام، مثل
`?mode=reading&fontSize=18&textWidth=88&reduceVisualNoise=true`.

## 5. قياس Lighthouse — قبل الإضافة وبعدها

يُشغَّل Lighthouse على نفس بناء Chromium مرتين: مرة والملف الشخصي محمَّلة فيه الإضافة عبر
`--load-extension`، ومرة بملف نظيف. المهم أن `chrome-launcher` يمرّر `--disable-extensions`
افتراضيًا، فيجب `ignoreDefaultFlags: true` وإعادة بناء قائمة الرايات يدويًا وإلا قِيس
المتصفح بلا إضافة في الحالتين. ويُزرع الملف الشخصي بالإعدادات المطلوبة قبل القياس حتى تُقاس
حالة مستقرة لا لحظة تثبيت. الإعداد `desktop`، والقيم وسيط 5 جولات (3 للصفحات الإضافية).

| الصفحة | التوليفة | الأداء | الوصولية | FCP | LCP | TBT | CLS |
|---|---|---|---|---|---|---|---|
| ويكيبيديا العربية | بدون | **96** | 80 | 1003 | 1029 | 0 | **0.0009** |
| ويكيبيديا العربية | تصميم 16px | 89 | 80 | 1010 | 1021 | 0 | **0.159** |
| ويكيبيديا العربية | قراءة 20px | 83 | 80 | 1063 | 1063 | 0 | **0.246** |
| ويكيبيديا الإنجليزية | بدون | **97** | 86 | 941 | 954 | 0 | 0.0009 |
| ويكيبيديا الإنجليزية | تصميم 16px | 88 | 86 | 941 | 950 | 0 | 0.196 |
| ويكيبيديا الإنجليزية | قراءة 20px | 88 | 86 | 944 | 958 | 0 | 0.201 |

ثلاث خلاصات:

1. **لا كلفة في سرعة التحميل.** FCP وLCP وSpeed Index بلا فرق يُذكر، وTBT صفر في كل توليفة
   على المقالات: المحرك يعمل بعد اكتمال التحميل لا أثناءه. عمل الخيط الرئيسي يتضاعف تقريبًا
   (413ms ← 806ms على ويكيبيديا العربية) لكنه يقع بعد TTI فلا يظهر في TBT.
2. **لا كلفة في الوصولية.** الدرجات متطابقة تمامًا في الحالات الاثنتي عشرة، وقائمة التدقيقات
   الساقطة نفسها. (لكن انظر «ما لا يراه Lighthouse» أدناه.)
3. **الكلفة كلها في ثبات التخطيط.** على المقالات فقط، وليس على قشرات التطبيقات ولا الصفحات
   الإخبارية التي يرفضها وضع القراءة.

### تفكيك الـCLS

| ما يتغيّر | CLS |
|---|---|
| تصميم 16px — والصفحة أصلًا 16px، فلا يتغيّر الحجم | 0.166 |
| تصميم 20px — خط + حجم (+25%) | 0.180 |
| تصميم 16px بخط Cairo | 0.146 |

أي أن **~92% من الانزياح هو تبديل الخط نفسه**، لا الحجم ولا المقاس. الخط الزمني يفسّر السبب:
الصفحة تُرسم عند 856ms، والمحرك يحقن أنماطه عند 1018ms وينزل أول علامة عند 1179ms — فهو
ينسّق صفحة **مرسومة**، وأي تنسيق بعد الرسم انزياح بالتعريف.

### ما لا يراه Lighthouse

تدقيق التباين يفحص الحالة الأولى للصفحة، قبل أن تعمل الإضافة. قياسٌ مباشر بعد التطبيق كشف
أن «تقليل التشويش البصري» عند `opacity: 0.58` كان يُسقط **14 من 14** عنصر تنقّل عُيِّن تحت
أرضية AA. صارت القيمة 0.75 وأُضيف استثناء لمن طلب تباينًا أعلى أو شفافية أقل من نظامه —
تفاصيل القياس في [ARCHITECTURE.md](ARCHITECTURE.md).

### ثلاثة «تحسينات» رفضها القياس

| التغيير | المتوقع | المقيس | القرار |
|---|---|---|---|
| بدء الفحص فورًا بلا `requestIdleCallback` | توفير 120ms | CLS 0.147 ← **0.456** | أُلغي |
| قراءة التخزين بالتوازي مع Service Worker | بدء أبكر | لا فرق، وأحيانًا إعادة بناء زائدة | أُلغي |
| `run_at: document_end` | حقن قبل الرسم | CLS **0.456** | رُفض |
| `run_at: document_start` | إلغاء الانزياح | 0.166 ← 0.147 فقط | لا يبرّر التغيير |

## 6. المتصفح الحقيقي عبر Playwright

بيئة `npm run harness` تحاكي `chrome.*`. لقياس ما لا تستطيع محاكاته — الشارة لكل تبويب،
جذور الظل، Service Worker حقيقي، تخزين حقيقي، ومنح `activeTab` — تُحمَّل الإضافة في Chromium
حقيقي:

```bash
npx playwright@latest install chromium
```

ثم شغّل سكربتًا يفتح `chromium.launchPersistentContext` مع
`--disable-extensions-except` و`--load-extension` يشيران إلى جذر المستودع، و
`--host-resolver-rules=MAP * 127.0.0.1:<port>` حتى تصير كل المضيفات مواقع حقيقية على خادم
محلي واحد — وهو ما يسمح باختبار قواعد المواقع على أصول متمايزة فعلًا.

نقطتان تعلّمناهما من هذه البيئة:

- اللوحة تُفتح كتبويب، فلا تكون هي التبويب النشط تلقائيًا. الترتيب الصحيح: افتح اللوحة، ثم
  `bringToFront()` على تبويب الموقع، ثم `reload()` على اللوحة — فتقرأ حينها التبويب الصحيح
  تمامًا كما تفعل في Brave.
- لا يمكن إطلاق `chrome.commands` من Playwright؛ سلوك الاختصارات مغطّى في
  `tests/background.test.mjs`.

## 7. قبل أي إصدار

1. `npm run verify`.
2. كرّر صفوف «تطبيق GitHub-like» و«تطبيق بلا مقال» و«تبديل `class`» عبر بيئة المتصفح أعلاه،
   خصوصًا بعد أي تعديل على `src/content/content.js`.
3. حمّل النسخة غير المضغوطة في Brave الحالي وجرّب **GitHub وYouTube وSubstack وويكيبيديا**
   وصفحة عربية وأخرى مختلطة. تحقّق أن الخط تغيّر وأن التخطيط لم يتحرك.
4. اختبر اللوحة على تبويب `brave://` وعلى تبويب عادي كان مفتوحًا قبل تثبيت الإضافة
   (يجب أن يظهر «أعد تحميل الصفحة»، لا «صفحة محمية»).
5. أعد تشغيل مجموعة Playwright على الأقل لصفوف «موقع تحكمه قاعدة» و«تغيير إعداد على صفحة
   كبيرة» و«Shadow DOM» بعد أي تعديل على `src/content/content.js` أو `src/popup/popup.js`.
6. `npm run package`.
